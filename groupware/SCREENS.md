# 화면 설계서 - 사내 그룹웨어 (연차 신청 · 승인)

> 기준 문서: [DESIGN.md](./DESIGN.md) (3. 시연 시나리오, 6. API 계약, 7. 화면 목록)
> 단일 페이지(SPA) 구성, 상단 사용자 전환으로 권한(`employee` / `manager`) 및 화면 전환을 즉시 시연한다.

---

## 0. 전체 구조 및 권한별 노출 정책

| 화면 / 영역 | `employee` (사원) | `manager` (팀장) | 비고 |
|---|---|---|---|
| **상단 바** | O | O | 사용자 전환 드롭다운 + 역할 배지 |
| **내 연차** | O | O | 기본 진입 탭 (잔여 카드 + 신청 내역) |
| **연차 신청** | O | O | `내 연차` 내 신청 패널 (`+ 연차 신청` 버튼으로 포커스) |
| **결재함** | **숨김** | **O** | `role === 'manager'`일 때만 탭·화면 노출, 대기 건수 배지 표시 |

- 사원 전환 시 `결재함` 탭이 활성 상태였다면 자동으로 `내 연차` 탭으로 복귀한다.
- 선택된 `userId`는 `localStorage`에 저장(`try/catch` 보호)해 새로고침 시에도 유지한다.

---

## 1. 상단 바 (공통)

### 와이어프레임
```text
+-----------------------------------------------------------------------------------+
| [사내 그룹웨어 | 연차·결재]   [ 내 연차 ]  [ 결재함 (1) ]*    [김신입 (개발팀) v] [사원] |
+-----------------------------------------------------------------------------------+
                                 * role === 'manager' 일 때만 노출
```

### 구성 요소 및 연동 API
| 구성 요소 | 설명 | 연동 API |
|---|---|---|
| 서비스 타이틀 | `사내 그룹웨어` + `연차 · 결재` 배지 | - |
| 탭 내비게이션 | `내 연차` / `결재함` (`manager` 전용, 대기 건수 배지 포함) | `GET /api/approvals?approverId=:id` (건수 반영) |
| 사용자 전환 드롭다운 | 데모용 로그인 대체 셀렉트 (`이름 (팀)` 형식) | `GET /api/users` |
| 역할 배지 | `employee` → `사원`, `manager` → `팀장` 색상 구분 표시 | `GET /api/users` 응답의 `role` |

### 상태 정의
- **로딩(Loading)**: 사용자 목록 조회 중 드롭다운 비활성화 및 `불러오는 중...` 표시
- **빈 상태(Empty)**: 사용자 목록이 비어 있을 때 `등록된 사용자 없음` 표시 및 본문 비활성화
- **오류(Error)**: `/api/users` 실패 시 상단 전역 오류 배너 + `다시 시도` 버튼 노출
- **성공(Success)**: 사용자 목록 바인딩 후 선택 사용자 기준 잔여·신청 내역·(팀장인 경우) 결재함 즉시 재조회

### 권한별 노출
- 서비스 타이틀과 사용자 전환 드롭다운·역할 배지는 모든 사용자에게 공통 노출된다.
- `결재함` 탭 버튼은 `currentUser.role === 'manager'`인 경우에만 표시된다.

## 2. 내 연차 (전체)

### 와이어프레임
```text
+-----------------------------------------------------------------------------------+
| 내 연차 현황                                                     [ + 연차 신청 ]  |
+-----------------------------------------------------------------------------------+
| +----------------+  +----------------+  +----------------+  +----------------+    |
| | 잔여 연차      |  | 사용 연차      |  | 승인 대기      |  | 총 부여 연차   |    |
| | 15일           |  | 0일            |  | 0일            |  | 15일           |    |
| +----------------+  +----------------+  +----------------+  +----------------+    |
+-----------------------------------------------------------------------------------+
| [3. 연차 신청 패널]  | 내 신청 내역                                         총 N건 |
| (좌측 400px)         | +------------+--------+------+------+------+-------------+ |
|                      | | 신청 기간  | 유형   | 일수 | 사유 | 상태 | 결재 의견   | |
|                      | +------------+--------+------+------+------+-------------+ |
|                      | | 12.01~12.02| 연차   | 2일  | 개인 | [대기]| -          | |
|                      | | 11.10      |오전반차| 0.5일| 병원 | [승인]| 확인했습니다| |
|                      | +------------+--------+------+------+------+-------------+ |
+-----------------------------------------------------------------------------------+
```

### 구성 요소 및 연동 API
| 구성 요소 | 설명 | 연동 API |
|---|---|---|
| 요약 카드 4종 | `잔여(remaining)` · `사용(used)` · `대기(pending)` · `총(total)` 연차 일수 | `GET /api/users/:id/balance` |
| `+ 연차 신청` 버튼 | 연차 신청 폼으로 포커스 이동 및 강조 | - |
| 내 신청 내역 표 | 최신순 목록: 기간, 유형, 일수, 사유, 상태 배지(`대기`/`승인`/`반려`), 결재 의견 | `GET /api/leave-requests?userId=:id` |

### 상태 정의
- **로딩(Loading)**: 사용자 전환 또는 갱신 시 카드·테이블 영역 로딩 안내(`불러오는 중...`) 표시
- **빈 상태(Empty)**: 신청 이력이 없을 때 테이블 영역에 `아직 신청한 연차 내역이 없습니다.` 안내 표시
- **오류(Error)**: 잔여 또는 신청 내역 조회 실패 시 상단 오류 배너에 API `error` 메시지 및 `다시 시도` 표시
- **성공(Success)**: 4개 연차 카드 수치와 최신순 신청 내역·상태 배지·결재 의견 렌더링

### 권한별 노출
- `employee`, `manager` 모두에게 동일하게 노출되며, 항상 현재 선택된 사용자의 본인 데이터만 조회한다.

## 3. 연차 신청 (전체)

### 와이어프레임
```text
+----------------------------------------+
| 연차 신청                              |
+----------------------------------------+
| 휴가 유형                              |
| [ 연차 (종일)                      v ] |  <- 연차 / 오전 반차 / 오후 반차
|                                        |
| 시작일              종료일             |
| [ 2026-12-01 ]      [ 2026-12-02 ]     |  <- 반차 선택 시 종료일 = 시작일 고정
|                                        |
| 예상 차감 일수:  2일  (주말 제외 평일) |  <- 클라이언트 실시간 미리보기
|                                        |
| 사유                                   |
| [ 개인 사유                        ]   |
|                                        |
| [!] 잔여 연차가 부족합니다 (가능: 13일) |  <- 4xx 응답 시 API error 메시지 표시
|                                        |
|                [ 초기화 ] [ 신청하기 ] |
+----------------------------------------+
```

### 구성 요소 및 연동 API
| 구성 요소 | 설명 | 연동 API |
|---|---|---|
| 유형 선택 | `annual`(연차), `half_am`(오전 반차), `half_pm`(오후 반차) | - |
| 기간 입력 | `startDate`, `endDate` (`YYYY-MM-DD`); 반차 선택 시 `endDate = startDate` 강제·잠금 | - |
| 예상 일수 미리보기 | 클라이언트 평일 수 계산(토·일 제외, 반차는 평일 시 `0.5일`) | - |
| 사유 입력 | 휴가 사유 텍스트 입력 | - |
| 오류/제출 영역 | 4xx `error` 인라인 경고 박스 + `신청하기` 버튼 | `POST /api/leave-requests` |

### 상태 정의
- **로딩(Loading)**: `POST /api/leave-requests` 전송 중 `신청하기` 버튼 비활성화(`신청 중...`)로 중복 제출 방지
- **빈 상태(Empty)**: 초기 진입 시 기본 날짜(오늘)·빈 사유·예상 일수 미리보기 표시
- **오류(Error)**: API 4xx 응답 시 `{ "error": "..." }` 메시지를 폼 내 경고 영역에 그대로 출력(예: 잔여 연차 부족, 주말만 선택, 기간 역전)
- **성공(Success)**: 201 응답 후 성공 토스트(`연차 신청이 접수되었습니다.`) 표시, 사유 초기화, 잔여 연차·내 신청 내역·(팀장 시) 결재함 자동 재조회

### 권한별 노출
- `employee`, `manager` 모두 사용 가능하다. (검증 규칙은 서버가 최종 판정하므로 잔여 초과 테스트 시에도 클라이언트에서 차단하지 않고 서버 오류를 노출한다.)

## 4. 결재함 (팀장 전용)

### 와이어프레임
```text
+-----------------------------------------------------------------------------------+
| 결재함                                                            대기 중인 요청 1건 |
+-----------------------------------------------------------------------------------+
| +-------------------------------------------------------------------------------+ |
| | 김신입  [연차]                                          신청일: 2026-11-26    | |
| | 기간: 2026-12-01 ~ 2026-12-02 (2일)                                           | |
| | 사유: 개인 사유                                                               | |
| |                                                                               | |
| | 결재 의견: [ 잘 쉬고 오세요                 ]     [ 반려 ]     [ 승인 ]       | |
| +-------------------------------------------------------------------------------+ |
+-----------------------------------------------------------------------------------+
```

### 구성 요소 및 연동 API
| 구성 요소 | 설명 | 연동 API |
|---|---|---|
| 대기 건 목록 | 같은 팀 구성원의 `pending` 신청(오래된 순), 신청자(`userName`)·유형·기간·일수·사유 | `GET /api/approvals?approverId=:id` |
| 결재 의견 입력 | 각 요청 카드별 의견 입력 필드 (`comment`) | - |
| `승인` 버튼 | 해당 건 승인 처리 후 목록에서 제거 | `POST /api/leave-requests/:id/approve` |
| `반려` 버튼 | 해당 건 반려 처리 후 목록에서 제거 | `POST /api/leave-requests/:id/reject` |

### 상태 정의
- **로딩(Loading)**: 목록 조회 중 로딩 표시; 개별 건 `승인`/`반려` 요청 중 해당 카드 버튼 비활성화(`처리 중...`)
- **빈 상태(Empty)**: 대기 건이 0건이면 `대기 중인 결재 요청이 없습니다.` 빈 상태 카드 표시
- **오류(Error)**: 403(권한/타 팀), 409(이미 처리됨) 등 4xx 응답 시 결재함 상단 오류 박스에 API `error` 메시지 표시
- **성공(Success)**: 200 응답 후 성공 토스트 표시, 결재함 목록·상단 배지 건수·잔여 연차·신청 내역 자동 새로고침

### 권한별 노출
- `currentUser.role === 'manager'`일 때만 탭과 섹션이 렌더링된다.
- `employee`는 `결재함` 탭 자체가 보이지 않으며 결재 API를 호출하지 않는다.

## 5. 시연 시나리오 화면 흐름 (DESIGN.md 3장)

```text
[1. 김신입 접속]
  상단 바: 김신입 (개발팀) [사원] | '결재함' 탭 숨김
  내 연차: 잔여 15일 / 사용 0일 / 대기 0일 / 총 15일
        │
        ▼ (연차 신청: 평일 2일 + 사유 입력 → POST /api/leave-requests → 201)
[2. 신청 직후 - 김신입]
  자동 재조회 → 잔여 15일, 대기 2일 반영
  내 신청 내역 최상단: [대기] 배지, 2일, 사유 표시
        │
        ▼ (상단 바 사용자 전환: 김신입 → 박팀장)
[3. 박팀장 전환]
  상단 바: 박팀장 (개발팀) [팀장] | '결재함 (1)' 탭 노출
  결재함 탭 클릭 → 김신입의 대기 1건 표시 (기간, 2일, 사유)
        │
        ▼ (결재 의견 입력 후 [승인] → POST /api/leave-requests/:id/approve → 200)
[4. 승인 처리 직후 - 박팀장]
  결재함 자동 재조회 → 해당 건 사라짐 → "대기 중인 결재 요청이 없습니다." 빈 상태
        │
        ▼ (상단 바 사용자 전환: 박팀장 → 김신입)
[5. 김신입 재확인]
  자동으로 '내 연차' 탭 복귀
  잔여 연차 13일 / 사용 연차 2일 / 대기 0일 확인
  내 신청 내역: [승인] 배지 및 팀장 결재 의견 표시
        │
        ▼ ((선택) 잔여 13일 초과 기간 신청 → POST /api/leave-requests → 400)
[6. 예외 검증]
  연차 신청 폼 오류 박스에 서버 메시지 출력:
  "잔여 연차가 부족합니다 (가능: 13일)"
```
